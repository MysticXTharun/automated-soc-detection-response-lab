\# Detection 003 - IOC Enrichment and SOC Risk Assessment



\## Overview



This detection extends the automated SOC lab by introducing IOC enrichment and analyst-focused risk assessment.



The Python enrichment utility accepts either a manually supplied IP address or a Wazuh alert JSON file. When a Wazuh alert is provided, the script automatically extracts the source IP address, classifies the IOC, performs reverse DNS resolution, determines whether public threat-intelligence enrichment is appropriate, and generates a SOC-oriented assessment.



This demonstrates how raw SIEM alerts can be transformed into enriched investigation context for SOC analysts.

\## Supported Input Modes



\### Manual IP Enrichment



The script can enrich an IP address supplied directly by an analyst.



```powershell

python ioc\_enrichment.py --ip 8.8.8.8

```



\### Wazuh Alert Enrichment



The script can also consume a Wazuh alert JSON file.



```powershell

python ioc\_enrichment.py --alert sample-wazuh-alert.json

```



The source IOC is automatically extracted from:



```text

data.win.eventdata.sourceAddress

```



This removes the need for an analyst to manually copy the source IP from the alert.



\## IOC Classification



The utility classifies IP addresses before performing threat-intelligence enrichment.



Possible classifications include:



\- Private IP

\- Public IP

\- Loopback IP

\- Multicast IP

\- Invalid IP



Private and other non-public addresses are not submitted to public threat-intelligence services.

\## SOC Assessment Logic



The script converts threat-intelligence results into a simplified SOC assessment.



| Condition | Verdict | Risk |

|---|---|---|

| Private/non-public address | INTERNAL | INFO |

| Threat intelligence unavailable | UNKNOWN | UNKNOWN |

| Provider whitelist match | BENIGN | LOW |

| Abuse score below 25 | LOW\_RISK | LOW |

| Abuse score 25-74 | SUSPICIOUS | MEDIUM |

| Abuse score 75-100 | MALICIOUS | HIGH |



These thresholds are intentionally simplified for the lab and should not be considered production detection policy.



Threat-intelligence reputation alone should not determine whether activity is malicious.

\## Security Considerations



The AbuseIPDB API key is read from an environment variable:



```text

ABUSEIPDB\_API\_KEY

```



The API key is not stored directly in the Python source code.



Secrets and API credentials should never be committed to a public Git repository.

\## Limitations



This implementation is designed for a controlled SOC lab.



Current limitations include:



\- IP IOCs only

\- Single threat-intelligence provider

\- Wazuh source-IP extraction based on a specific Windows event structure

\- Simplified reputation thresholds

\- No API result caching

\- No rate-limit management

\- No automatic Wazuh alert ingestion

\- No automated incident report generation
