\# Detection 012 - Automated Incident Timeline Reconstruction

\## Overview

Detection 012 adds automated incident timeline reconstruction to the \*\*Automated SOC Detection \& Response Lab\*\*.

Security investigations often require analysts to combine events generated by different detection, triage, case-management, notification, and risk-assessment systems.

This detection collects timestamps from multiple SOC automation stages, normalizes them to UTC, sorts them chronologically, calculates elapsed time between activities, and generates both machine-readable and analyst-readable incident timelines.

The engine processes:

\- Original security alert time

\- Automated triage completion

\- SOC case creation

\- Notification generation

\- Incident risk assessment

\## Timestamp Normalization

Different components may produce timestamps in slightly different ISO 8601 formats.

Examples:

```text

2026-08-13T05:14:03.915+0000

2026-08-14T03:39:46.338412+00:00

```

The reconstruction engine parses these formats and normalizes them to UTC.

Normalized example:

```text

2026-08-13T05:14:03.915000+00:00

```

This allows events from different sources to be compared and sorted consistently.

\## Event Time vs Processing Time

Detection 012 preserves an important distinction between security-event time and automation-processing time.

\### Event Time

The original security event occurred at:

```text

2026-08-13T05:14:03.915000+00:00

```

This represents when the monitored activity occurred.

\### Processing Time

Later timestamps represent when different automation components processed the incident.

Examples include:

```text

TRIAGE\_COMPLETED

CASE\_CREATED

NOTIFICATION\_GENERATED

RISK\_ASSESSMENT

```

Maintaining this distinction prevents processing delays from being incorrectly interpreted as attacker activity.

\## Limitations

This implementation is designed for a controlled SOC lab.

Current limitations include:

\- Local JSON evidence input

\- Small predefined event dataset

\- No direct Wazuh API ingestion

\- No SIEM event search

\- No endpoint telemetry ingestion

\- No automatic timezone discovery

\- No distributed log-source clock-drift correction

\- No persistent timeline database

\- No graphical timeline visualization
