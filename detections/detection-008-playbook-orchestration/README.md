# Detection 008 - Automated SOC Playbook Orchestration

## Overview

Detection 008 connects the previously independent SOC automation components into a single orchestrated playbook.

The playbook accepts a Wazuh alert and supporting context, then automatically executes the following workflow:

- IOC enrichment
- Context-aware alert triage
- Automated incident reporting
- Automated case management
- SOC notification and escalation
- Final playbook summary generation

This transforms the project from a collection of separate automation scripts into a simplified SOAR-style workflow.

## Playbook Inputs

The orchestrator requires three inputs.

### Wazuh Alert

The original Wazuh alert JSON contains:

```text
Rule ID
Rule Level
Source IP
Destination IP
Destination Port
MITRE ATT&CK metadata
```

### Asset Context

The asset context provides:

```text
Hostname
Asset Type
Criticality
Business Context
```

### Response Context

The response context describes the outcome of automated containment.

Successful response:

```text
Containment Status: SUCCESS
Automatic Recovery: True
```

Failed response:

```text
Containment Status: FAILED
Automatic Recovery: False
```

---

## Single-Command Execution

The complete playbook can be executed with one command:

```powershell
python playbook_orchestrator.py `
--alert sample-wazuh-alert.json `
--assets asset-context.json `
--response response-context.json `
--output-dir run-100111
```

The orchestrator automatically executes every automation stage in sequence.

---

## Execution Stages

1. IOC Enrichment
2. Automated Alert Triage
3. Automated Incident Reporting
4. Automated Case Management
5. SOC Notification and Escalation
6. Playbook Summary Generation

Each stage must complete successfully before the workflow continues.

---

## Failure Handling

Every automation stage is checked before the next stage executes.

If a component fails:

```text
[FAILED] <Stage Name>
```

the playbook stops instead of continuing with incomplete or unreliable data.

This prevents downstream automation from operating on invalid results.

## Security Considerations

The orchestrator does not contain API credentials.

Threat-intelligence credentials remain handled by the upstream enrichment component through environment variables.

The orchestrator passes structured files and command-line arguments between trusted lab components.

Secrets and credentials should never be committed to the Git repository.

## Limitations

This implementation is designed for a controlled SOC lab.

Current limitations include:

- Local subprocess orchestration
- Local JSON and Markdown artifacts
- No persistent workflow engine
- No automatic Wazuh API ingestion
- No retry policy
- No workflow state database
- No concurrency
- No approval gates
- No rollback logic
- No external SOAR platform
